## Fix automatic routing calibration — !404

**Branch:** `feature/scan-automatic-routing`

### Problem

The viewer disables Automatic route because approved scans have incorrect calibration metadata.

Current scan:
```json
{
  "coordinateSystem": {
    "units": "relative",
    "upAxis": "Y",
    "calibrated": false
  },
  "alignmentVerified": true
}
```

The parent space is already calibrated in metres.

Users should not have to manually configure calibration for every iPhone LiDAR scan.

### Task

1. Trace calibration metadata through the capture contract, CPU processor, worker, revision approval, scan API and frontend.
2. Ensure validated, metric-scale ARKit captures automatically retain `units: "metres"` and `calibrated: true` when appropriate.
3. For a **single scan**, don't require manual multi-scan alignment verification if its coordinate frame and scale are already validated.
4. Keep strict verification for imported models with unknown scale and for multi-scan alignment.
5. Provide a supported owner action to correct calibration metadata on existing scans, instead of requiring direct SQL updates.
6. Preserve existing Auth0 authorization, scan visibility and sharing rules.
7. Add tests covering automatic calibration, unverified scans and viewer eligibility.

### Important

- Do not blindly mark all scans calibrated.
- Do not treat `alignmentVerified: true` as proof of metric scale.
- The existing `mock-lidar` scan is synthetic and should remain uncalibrated unless explicitly verified.
- Do not modify production database records.
- Preserve current routing functionality.

A validated, metre-scale iPhone LiDAR scan can be approved, opened and routed through **without manually checking calibration boxes**.
