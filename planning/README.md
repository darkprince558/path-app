# Team planning

Open the [roadmap](ROADMAP.md) to see the next demonstration, who owns each part and how to tell when it works. To change the order or suggest a milestone, use [Edit roadmap on GitHub](https://github.com/darkprince558/path-app/edit/main/planning/ROADMAP.md) and describe the change in the PR.

| If you are… | Go here |
| --- | --- |
| Picking up work | [Live team board](https://github.com/darkprince558/path-app/issues/8) · [Create a task, claim one or post a checkpoint](../docs/tasks.md). |
| Building the offline website | [Camera-only capture, local and live server previews, resumable uploads and guest access](offline-web-product.md), including release gates and physical-device trials. |
| Designing a change | [Architecture](../docs/architecture.md), [capture format trial](../docs/scan-formats.md), or [deployment plan](../docs/deployment.md). Put a new proposal in this folder when it needs its own discussion. |
| Preparing the demo | [Gemini landmark flow](../docs/gemini-demo.md) and [prize demo plan](../docs/prize-plan.md). |
| Looking up why we made a choice | [Team notebook](../knowledge/README.md). |
| Starting an agent session | [Teammate setup](../prompts/team-chat.md) and [task prompt](../prompts/start-task.md). |

For a new plan, start with the user outcome, name the owner and affected teammate, link the issue, and describe one observable acceptance check. Use the roadmap to link the plan when it changes the order of work.
